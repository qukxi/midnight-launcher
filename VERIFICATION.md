# Проверка Midnight Launcher 0.2.0

## Установщик в стиле Midnight — 2026-11-01

Windows NSIS-установщик получил фиолетово-розовое оформление лаунчера: фирменную боковую иллюстрацию, пиксельный логотип, тёмные страницы, скруглённые кнопки, флажки и полосу прогресса. Палитра генерируется из `src/theme.css`, русские и английские тексты — из `src/i18n.ts`. Небольшая x86 DLL меняет отрисовку стандартных элементов NSIS; установка WebView2, обновление, ярлыки, регистрация и удаление используют стандартный шаблон Tauri.

Проверено:

- `npm test`: **39 тестов прошли**. `npm run build:win -- --ci -- --locked` успешно выполнила TypeScript/Vite build, собрала Windows x64 EXE, нативную тему и NSIS-пакет. После исправления локализации пакет повторно собран через `tauri bundle`.
- `npm run verify:installer:win` создаёт отдельный пакет с уникальными именем продукта и ключами реестра. В последнем запуске `6471f174` прошли тихая установка в путь с пробелами, проверка SHA-256 установленного EXE против release EXE, повторная установка и удаление. Посторонний тестовый файл сохранился после обеих операций. Отчёт: `artifacts/installer verification/6471f174/result.json`.
- В настоящих Windows-окнах проверены английские страницы приветствия, обслуживания и выбора папки, видимость поля пути, тёмное оформление кнопок «Назад»/«Далее»/«Обзор», русское приветствие и переход клавишей Enter. Одноязычный русский проверочный пакет корректно показывает русские стандартные кнопки даже при английском языке Windows. Предварительный просмотр закрыт без установки основной копии.
- Готовые EXE, установщик размером **5 541 993 байта**, SHA-256, копия отчёта и снимки окон сохранены в `artifacts/windows/branded-installer/`. Русский снимок получен из изолированного проверочного пакета, поэтому в заголовке есть `Installer Check`.

Игры и Java в этой проверке не устанавливались. Первый запуск на системе без WebView2, подписывание Windows-пакета, macOS и авторизованный игровой процесс отдельно не проверялись.

## Крупные моды: Wonderland.jar — 2026-10-31

Ошибка со скриншота воспроизведена по официальным метаданным Modrinth: Wonderland.jar 3.0.3 для Forge / Minecraft 1.20.1 весит **175 374 232 байта** (около 167,25 МиБ), что превышало прежние ограничения 64 МиБ на JAR и 128 МиБ на установку. Лимит файла увеличен до **512 МиБ**, каталожной установки — до **2 ГиБ** при прежнем ограничении 64 зависимостей. Лимит локального импорта и тексты RU/EN синхронизированы.

Каталог теперь пишет загрузки по частям во временную папку `.midnight-catalog-<uuid>` внутри проверенной папки модов. Размер, SHA-1 и SHA-512 проверяются при чтении потока; полные JAR всех зависимостей не хранятся вместе в памяти. После проверки всего набора файлы публикуются через hard links с запретом перезаписи. Ошибка/отмена очищает временные файлы; откат удаляет только неизменённые файлы текущей попытки. Проверка существующих файлов и их metadata тоже использует чтение с диска; ZIP не распаковывается. Списки разрешённых HTTPS-хостов, ограничения редиректов и правила передачи ключа CurseForge сохранены.

Прогресс загрузки показывает полученные/общие МиБ и полосу; отмена доступна во время чтения потока. Файловым запросам разрешено до 30 минут, API-запросы сохраняют прежний тайм-аут 90 секунд.

Проверено:

- `npm test`: **39 тестов прошли**. TypeScript/Vite production build и `cargo check --tests --examples --locked --offline` прошли.
- **82 Rust-теста прошли** на Windows x64. Добавлены проверки реальных метаданных Wonderland, лимитов обоих API, общей границы 2 ГиБ, проверки чанков, усечённого/увеличенного тела, повреждённого SHA-512, отмены посреди потока, публикации и очистки staging. Как ранее, в Windows test EXE встроен стандартный манифест Tauri через `mt.exe`.
- Реальный `examples/verify_catalog.rs` установил Wonderland.jar **3.0.3** (project `IXZPFrP2`, release `Xw8Geo0z`, 175 374 232 байта) и обязательный **GeckoLib 4.8.4** (1 038 209 байт). Сумма — 176 412 441 байт. Размеры и хеши получены с официального Modrinth API и проверены при скачивании.
- Первая установка добавила **2 файла**, повторная — **0 файлов**, переиспользовала **2**. После обеих попыток временных папок и `.part` в папке модов нет. Пользовательские сборки и аккаунты не использовались; проверка изолирована в `artifacts/catalog large mod verification/`, отчёт — `catalog-check.json`.
- `cargo fmt --check` и Windows EXE/NSIS build прошли. Новый установщик, EXE, SHA-256 и копия отчёта находятся в `artifacts/windows/large-mods/`. Интерфейс готового EXE в этой проверке отдельно не открывался.

Это проверка скачивания и установки, без запуска сторонних JAR и игрового процесса. Совместимость Wonderland с другими модами, авторизованные серверы, реальная загрузка CurseForge с ключом и сборка macOS здесь не проверялись.

## Forge и NeoForge — 2026-10-31

В создание и редактирование Java-сборок добавлены Forge и NeoForge. Совместимые версии загружаются автоматически с официальных серверов при выборе Minecraft или загрузчика; выбранная версия закрепляется в сохранённой сборке. При смене Minecraft/загрузчика прежний выбор сбрасывается, запоздалый ответ предыдущего запроса не применяется. Браузерное превью позволяет вводить версию вручную и объясняет, что автоматический список доступен в приложении. Подписи, поиск библиотеки и каталог модов учитывают точный загрузчик.

Rust получает официальный installer JAR с проверкой размера и SHA-1, проверяет библиотеки и выполняет только клиентские processors через выбранную Java без shell. Mojang mappings скачиваются общим ограниченным downloader. Пути, ZIP entries и Maven coordinates проверяются; разрешённые download hosts дополнены только официальными Maven Forge и NeoForge. Результаты подготовки изолированы по Minecraft и загрузчику; SHA-256 receipt проверяет файлы перед повторным использованием. Есть прогресс и отмена подготовки. Для Windows добавлено ограниченное повторение переименования подготовленной Java, если ОС временно удерживает её файлы после проверки версии.

Для BootstrapLauncher подготовленный Minecraft исключён из classpath, чтобы не создавать дублирующие модули. Новый FML сохраняет исходный клиент в classpath и находит подготовленный JAR через собственный Maven-каталог; это сохраняет production discovery. Регрессия проверяется на официальных профилях Forge 1.20.1, NeoForge 1.21.1 и NeoForge 26.3. Схема сверена с [официальным GameLocator FML](https://github.com/neoforged/FancyModLoader/blob/main/loader/src/main/java/net/neoforged/fml/loading/moddiscovery/locators/GameLocator.java).

Modrinth и CurseForge фильтруют поиск, релизы и обязательные зависимости по Minecraft и Fabric/Forge/NeoForge. Конфликты ID проверяются также в `META-INF/mods.toml` и `META-INF/neoforge.mods.toml`, включая несколько `[[mods]]`. Modrinth-модпаки принимают один из трёх загрузчиков из manifest и сохраняют его точную версию. Смешанные зависимости загрузчиков отклоняются. Реальное скачивание модов/модпаков Forge и NeoForge в этой проверке не выполнялось; фильтрация и импорт их metadata покрыты тестами.

Проверено:

- Все 38 Vitest-тестов и 78 Rust-тестов прошли. Windows Rust test EXE, как и ранее, запущен после встраивания стандартного манифеста Tauri через `mt.exe`.
- Production frontend успешно собран с проверкой TypeScript.
- `examples/verify_loaders.rs` реально установил и запустил Forge **47.4.28 / Minecraft 1.20.1 / Java 17**, NeoForge **21.1.265 / Minecraft 1.21.1 / Java 21** и NeoForge **26.3.0.100 / Minecraft 26.3 / Java 25**. Каждый процесс оставался активным 45 секунд; собственный `latest.log` подтвердил готовность звука и атласов текстур без ошибки старта FML. Повторные проверки использовали проверенный кэш результатов processors.
- Проверки изолированы в `artifacts/windows verification/` (путь с пробелом); тестовые инстансы — `loader-check-<loader>-<minecraft>`, имя игрока — `LoaderCheck`. Пользовательские игровые папки и Microsoft-сессии не использовались. Тестовые процессы остановлены проверочным примером.
- Отчёты `forge-1.20.1-check.json`, `neoforge-1.21.1-check.json`, `neoforge-26.3-check.json` находятся в `artifacts/windows/forge-neoforge/`. Они явно указывают `authenticated: false`, `gameplayTested: false`, `rendererReady: true`.

Поддержка ограничена современным Forge 38+ для Minecraft 1.18+ и NeoForge из `net.neoforged:neoforge` для Minecraft 1.20.2+ / 26.x. Старый Forge, NeoForge fork для 1.20.1 и Quilt не реализованы. Microsoft-вход, авторизованные серверы, игровой процесс в мире, произвольные сторонние моды и macOS-запуск этой проверкой не подтверждаются.

## Библиотека сборок: оформление и UX — 2026-10-31

Вкладка «Сборки» вынесена в `InstancesPage.tsx`. Выбранная сборка показана отдельным блоком с запуском, настройкой и доступом к Java-модам. Запуск использует общий с главной страницей обработчик и прежний IPC. Карточки показывают версию Minecraft / Horizon, загрузчик и происхождение Modrinth. Геометрические обложки используют сохранённый цвет сборки и не масштабируют текст.

Добавлены фильтры Java/Horizon и поиск по названию, версии, загрузчику и названию релиза модпака. Пустой результат предлагает сбросить поиск и фильтр. Редкие действия находятся в меню карточки. Удаление записи требует подтверждения и объясняет, что файлы остаются на диске; последняя запись защищена, а при удалении выбранной назначается существующая сборка. При выполнении операции или работающей игре изменение выбранной сборки и удаление заблокированы.

Форма создания сначала показывает название, движок, версию и загрузчик. Память, Java и цвет раскрываются отдельно. При открытии курсор находится в названии. Horizon скрывает Java-загрузчики и параметры памяти. Сохранение настроек Java-сборки сохраняет метаданные установленного модпака.

Проверки: 34 Vitest-теста прошли, включая поиск с несколькими словами, старые Java-записи без engine, совместное применение запроса и фильтра, выбор замены и защиту последней сборки. TypeScript/Vite build и финальная Windows EXE/NSIS build прошли. В браузере проверены отсутствие результата и сброс, фильтр Java, переключение сборки, создание/отмена, выбор Horizon, раскрытие дополнительных параметров, подтверждение/отмена удаления и возврат фокуса в карточку. Исходная выбранная сборка восстановлена; существующие записи и файлы в этой UI-проверке не удалялись.

Макет проверен при 1160×820 и 640×480: горизонтального переполнения нет, форма с раскрытыми параметрами прокручивается, поле названия и поля параметров сохраняют размер шрифта 14 px. В штатном размере действия первого ряда находятся в видимой области. Финальный EXE запущен и визуально проверен в Windows с тремя сохранёнными сборками, английским языком и темой Charcoal & Ivory. Запуск игры, загрузка сборок и новая авторизация в рамках этой проверки не выполнялись.

Готовые EXE, установщик, SHA-256 и снимки находятся в `artifacts/windows/instance-library/`. Браузерное превью открывается сразу на библиотеке по `http://127.0.0.1:1420/#instances` и оставлено открытым.

## Оффлайн-профиль после Microsoft-входа — 2026-10-31

Оффлайн-режим Java и Horizon требует ранее подтверждённого Microsoft-аккаунта с лицензией Minecraft Java и корректным игровым профилем. Источник подтверждения — действующая либо ранее проверенная Rust-сессия / профиль в системном хранилище. Сохранённый ник и незавершённый Microsoft-вход доступа не дают. Выбор проверяется отдельной IPC-командой, а запуск — до подготовки и повторно перед созданием процесса. Повторная Microsoft-авторизация для явно выбранного оффлайн-режима не выполняется. Выход удаляет подтверждение, сбрасывает оффлайн-ник и блокирует форму. Локально сохранённый аккаунт отображается в «Аккаунтах» и позволяет выйти без сетевого восстановления. При старте приложения системное хранилище автоматически не читается.

Restore перенесена под кнопку Microsoft с отступом 12 px; кнопки переносят длинный текст в небольших окнах. Тексты обновлены на русском и английском.

В готовом Windows EXE визуально проверены отдельная строка Restore, отступ между кнопками, прокрутка к оффлайн-профилю и доступность нижней навигации. В состоянии без подтверждённого аккаунта accessibility-дерево показывает поле ника и кнопку оффлайн-профиля как disabled; подсказка о необходимом Microsoft-входе видна. Проверка выполнялась в стандартном окне; уменьшение окна до минимального размера в этой проверке не подтверждено. Новый Microsoft-вход через браузер автоматически не выполнялся.

## Minecraft Java: перенос на Windows x64 — 2026-10-29

Убрана привязка Java-установщика к Apple Silicon. Новый модуль платформы определяет Windows x64 и получает версию ОС через RtlGetVersion. Правила Mojang выбирают Windows x64 библиотеки и корректно обрабатывают OS version/architecture. Поддерживаются современные natives-artifacts и старые classifiers с `${arch}`. DLL распаковываются в отдельный `natives-windows-x64`; macOS ARM64 использует собственный набор.

Java 17/21/25 автоматически выбирается по версии игры и устанавливается для платформы: Windows x64 ZIP или macOS ARM64 tar.gz. Проверяются размер, SHA-256, версия Java и архитектура JVM. ZIP-распаковка запрещает traversal, Windows device names, симлинки, дубликаты и чрезмерный размер; отмена проверяется во время распаковки. Windows-процессы запускаются без дополнительного консольного окна. Classpath использует `;`, macOS-параметр `-XstartOnFirstThread` на Windows не добавляется. Horizon на Windows также использует общую автоустановку Java 25.

Проверки:

- 27 Rust-тестов прошли в Windows release-тестовом бинарнике со стандартным манифестом Tauri; 13 frontend-тестов прошли.
- Реально скачаны и проверены Minecraft 1.21.1, 54 библиотечных архива и 3888 уникальных ресурсов; DLL извлечены из 8 Windows natives-архивов. Автоматически скачана и проверена Temurin JRE 21.0.13 x64, архив 49 106 397 байт.
- Реальная проверка использует путь с пробелами `artifacts/windows verification/`. Minecraft запущен теми же Rust-функциями `minecraft::install`, `java::ensure`, `launch::start`, что используются лаунчером. Процесс оставался работающим через 30 секунд; лог подтверждает LWJGL 3.3.3, загрузку текстур и запуск OpenAL.
- При повторном запуске в окне Minecraft 1.21.1 визуально наблюдался экран создания мира. Создание и игровой процесс внутри мира не подтверждались.
- Первая проверка сохранена в `artifacts/windows verification/windows-first-launch.json`. Тестовое имя — MidnightCheck, Microsoft-сессия не восстанавливалась. Логи находятся в `artifacts/windows verification/logs/minecraft-windows-smoke.log` и в папке тестового инстанса.

Это подтверждение установки и офлайн-запуска Vanilla 1.21.1 на Windows x64. Оно не подтверждает Microsoft-вход, игру на серверах с проверкой лицензии, игровую сессию в мире, все версии Minecraft или запуск самого Horizon. Ограничение одобрения Microsoft API не менялось. Предыдущие записи о том, что Java-инсталлятор работает только на Apple Silicon, этой проверкой отменяются.

Итоговая Windows-сборка после переноса: `npm run build:win -- --ci -- --locked` прошла. Обновлены оба файла в `artifacts/windows/` и SHA256SUMS.txt. Итоговый EXE (16 490 496 байт) повторно запущен и оставался работающим при startup-проверке; NSIS-установщик — 4 779 952 байта. Официальный `cargo fmt --check` прошёл.

Дополнение к визуальной проверке: второй, расширенный `--inspect`-запуск был закрыт с кодом 0 до завершения 120-секундного таймера.
